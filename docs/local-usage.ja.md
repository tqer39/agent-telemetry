# ローカル利用量レポート

Claude CodeとCodexのローカルセッションログから、トークン効率の改善候補を確認するツールです。
レポート処理はPythonの標準ライブラリを使い、LLMやAPIキーは不要です。
Zstandard圧縮ログを含む集計には、`compression.zstd` が使えるPython 3.14以降を使用してください。
通常はmiseで固定したPython 3.13.18を使います（パッケージの最低要件は3.12）。
3.13ではZstandardを未読取として件数を示し、非圧縮・gzipログの集計を継続します。
既存の `mise run report` は表形式の集計として維持し、HTML版は `mise run usage:report` で起動します。

## 使い方

リポジトリのルートで実行します。

```bash
uv run --locked --project session-indexer agent-telemetry --timezone Asia/Tokyo --open
```

直近30日分の `report.html` を生成してブラウザで開きます。
使用量の集計に加え、消費の大きいセッション、入力推移、根拠付きの改善ヒントを表示します。
自動更新はありません。更新時はコマンドを再実行し、ブラウザを再読み込みしてください。

```bash
# 当日分 / 圧縮済みの過去ログも含む全期間（当日まで）
uv run --locked --project session-indexer agent-telemetry --days 1 --timezone Asia/Tokyo
uv run --locked --project session-indexer agent-telemetry --days 0 --timezone Asia/Tokyo --open

# 集計結果をJSONとして取得
uv run --locked --project session-indexer agent-telemetry --json
uv run --locked --project session-indexer agent-telemetry --json --output report.json

# 別の保存場所を指定
uv run --locked --project session-indexer agent-telemetry --claude-dir /path/to/claude/projects --codex-dir /path/to/codex
```

既定の読取先は `~/.claude/projects`、`~/.codex/sessions`、`~/.codex/archived_sessions` 以下の
`.jsonl`、`.jsonl.zst`、`.jsonl.gz` です。各ディレクトリを再帰的に検索します。
圧縮ログはメモリ上で順に読み取り、展開済みファイルを保存しません。
`CLAUDE_CONFIG_DIR` と `CODEX_HOME` にも対応します。明示したオプションを優先します。
タイムゾーンを省略するとOSのローカル時刻で日別集計します。

## 作業中の圧縮・引き継ぎヒント（hooks）

Claude CodeとCodex向けのcommand hookを用意しています。LLM・API・全ログの再集計は使いません。
イベントで渡された情報だけを処理し、元のツール結果や会話を変更しません。

| イベント | 条件 | 出力 |
| --- | --- | --- |
| PostToolUse | ツール結果が2万文字以上 | ユーザー向けの範囲絞り込み・引き継ぎヒント |
| SessionStart | sourceがcompact | モデル向けの短い圧縮後リマインダー |

圧縮後には、目的・制約・決定事項・変更ファイル・未完了項目・検証結果・次の一手を確認するよう促します。
元ログの全文再読込や、推測での補完は促しません。新規開始・resume・forkでは出力しません。
出力へのヒントは `systemMessage` のみで、追加コンテキストをモデルへ注入しません。
圧縮後だけ `hookSpecificOutput.additionalContext` を使います。表示はクライアントのhook対応に依存します。

同一セッション・種類ごとに15分の間隔を設け、同時にhookが動いても通知を重複させません。
状態は `~/.cache/agent-telemetry/hook-tips/notifications.sqlite3` にセッションと種類のハッシュ・通知時刻だけを保存します。
本文・コマンド・ツール結果・元ログのパスは保存せず、通知へも転記しません。
通知状態を保存できない場合は無出力にし、繰り返しの通知を避けます。

### 登録

リポジトリのルートで、現在のPythonとスクリプトの絶対パスを使った設定を生成できます。

```bash
mise run usage:hook-config
```

生成JSONの `hooks` を、Claude Codeでは `.claude/settings.local.json`、
Codexでは `.standards/hooks.local.json` の既存設定へマージしてください。他のhookを置き換えないでください。
Codexの生成物 `.codex/hooks.json` は直接編集せず、`standards:plan` と `apply` で再生成します。
この変更はhookを自動登録しません。生成したcommandには機器固有の絶対パスが含まれるため、共有前に確認してください。
別のclone・worktreeで使う場合やPython・スクリプトの配置を変えた場合は、設定を生成し直します。
ユーザー全体の設定ファイルは変更していません。

Codexでは `/hooks` で定義を確認・信頼してから有効になります。
設定再読込のため、必要に応じてクライアントを再起動してください。
クライアントのバージョンや実行環境でのイベント発火・画面表示は、実際に確認する必要があります。

### 動作と制約

- 既定の入力上限は2MiBです。JSON不正・入力超過・未知のイベントは終了コード0・無出力です。
- 文字数は文字列の長さ、構造化された結果はJSON表現の文字数です。入力トークン数への換算はしません。
- `--threshold` で文字数、`--cooldown` で通知間隔、`--state-dir` で状態保存先を変更できます。
  設定JSON内のcommandへ引数を追加してください。
- 圧縮を強制実行せず、結果の切り詰め・自動要約・ファイル削除・hookによる作業の停止もしません。
- 会話全体のトークン残量は推定しません。大きな出力の直後と、圧縮後の助言に限定します。
- 通知済みの状態を削除すると、次の該当イベントで再通知されます。

仕様の確認元: [Claude Code hooks](https://code.claude.com/docs/en/hooks)、
[Codex hooks](https://learn.chatgpt.com/docs/hooks)。

## LLM不要の自動分析

毎回同じルールで、優先して確認するセッション・原因候補・最初に試す改善・検証方法を出力します。
LLM、APIキー、外部通信は使いません。HTMLにも既定条件の上位5件を表示します。

```bash
# ログを集計して、そのまま分析文を標準出力へ
uv run --locked --project session-indexer agent-telemetry --days 0 --timezone Asia/Tokyo --analyze

# 保存済みの集計だけで再分析（元ログもGitも読み直さない）
uv run --locked --project session-indexer agent-telemetry --analyze --from-report report.json --output analysis.txt
uv run --locked --project session-indexer agent-telemetry --analyze --from-report report.json \
  --json --output analysis.json

# 選出数・最低消費量を調整
uv run --locked --project session-indexer agent-telemetry --analyze --from-report report.json \
  --top 3 --min-tokens 1000000
```

`--from-report` の期間・タイムゾーン・生成日時は保存済み集計のものです。
新しい利用分を含めるには、先に `--json --output report.json` で集計を更新してください。
集計JSONの追跡情報やヒントが不足している場合も、最新版での再集計が必要です。
`--analyze --json` は分析結果のみ、通常の `--json` は全集計を出力します。
`--analyze` の出力先を省略すると標準出力です。`--open` はHTML生成時のみ使用できます。

### 確認順の決め方

既定は総量10万tokens以上で、既知の改善候補があるセッションから最大5件を選びます。
選定指標は総トークン量×兆候の重みで、重みは反復3、エラー候補2、大きな出力2、入力増加1、低キャッシュ1です。
大きな出力＋入力増加、または反復＋エラー候補3件以上の組ごとに重みを1加算します。
同点なら総量の降順、ツール名・セッションIDの昇順で選び、同じ集計から同じ結果を生成します。

反復上位グループで確認できた待機・状態確認が反復の半数以上かつ3回以上なら、反復の重みを1に下げます。
この場合はエラーとの組による加点もしません。既知の待機ツール名の完全一致で判断し、
ツール引数を再解釈して待機と推測することはしません。上位グループ以外の待機は識別できません。
待機自体を短くするのではなく、待機後のモデル再呼出・状態確認の頻度を確認する改善案を出します。

反復と複数のエラー候補がある場合は実行条件の確認、大きな出力と入力増加がある場合は出力の絞り込みを優先します。
それ以外は重みが最大の候補を最初に選びます。各候補には数値の根拠・元ログの参照先・
最初の改善手順・変更後の検証方法を付けます。入力不足による不明件数や集計時の除外情報も表示します。

この指標は調査の順番で、効率の点数・推定削減量・金額ではありません。
選出セッションの総量構成比も、削減できる割合を意味しません。
兆候の同時発生は因果関係を証明しないため、改善を一つずつ試し、成果・品質を維持できるか確認してください。

## 効率を確認する流れ

1. 「消費の大きいセッション」で総量・構成比・キャッシュ読取率・入力/記録を比較します。
2. セッションのリンクで移動し、セッションの見出しを選んで詳細を開きます。リポジトリ別の集計からも移動できます。
3. 入力推移と「観測事実と改善のヒント」を確認します。
4. 消費上位10記録の日時・モデル・直前のツール名を見て、元ログの行番号で内容を確認します。
5. 必要に応じて作業を変え、同程度の目的・モデル・完了条件の作業で再確認します。

総量の多さ、キャッシュ率、出力の少なさだけでは非効率と断定しません。
完了・成果・品質・ユーザーの手戻りはログだけでは評価しておらず、総合点や「問題なし」の判定は出しません。
ヒントに該当しない場合も、その検出条件に該当しないという意味です。

### 指標と改善ヒント

すべて選択した期間内の記録を使います。検出条件は固定の目安で、最適値ではありません。

| 指標・候補 | 定義・検出条件 | 確認・改善の例 |
| --- | --- | --- |
| キャッシュ読取率 | キャッシュ読取 / 入力。入力10万以上かつ50%未満で候補 | 固定の指示・前提の変化を確認。新規作業では低くても正常 |
| キャッシュ読取を除く入力 | 入力 − キャッシュ読取。キャッシュ書込も含む | 読取率と併せて比較。金額・無駄な量・新規の固有トークン数ではない |
| 入力/記録 | 入力合計 / 使用量記録数 | 同じ形式・モデル・目的で比較。記録単位はツールや形式で異なる |
| 入力増加 | 6記録以上。末尾1/3の入力中央値が先頭1/3の2倍以上かつ2万以上 | 大きな出力や長期化を確認。引き継ぎ情報を残して独立作業を分ける |
| 同一引数の反復 | 同一ツール名・同一引数の追加実行が3回以上 | 結果の引き継ぎを確認。監視・ポーリング・変更後の再検証は必要な反復の場合あり |
| ツールのエラー候補 | 明示的なエラーフラグ、終了コードが非ゼロ | 実行条件・依存関係を確認。検索の該当なしなど正常な非ゼロ終了もある |
| 大きなツール出力 | 最大の結果が2万文字以上 | 検索・ファイル読取・テスト出力の範囲を絞れるか確認 |
| コンパクション | 明示的な圧縮イベントの件数 | 会話の長期化を見る補助情報。回数だけで改善対象とは判断しない |

入力推移は記録順に最大60点を等間隔抽出します。縦軸は表示サンプルの最大値です。
省略したピークは消費上位の表で確認してください。入力増加の判定は抽出前の全記録を使います。
先頭・末尾の1/3は記録数を3で割った整数部分を使います。
モデル変更・作業内容の変化でも入力は増えるため、モデル一覧と元ログを併せて確認してください。
キャッシュ項目が欠損・不正なら率や非読取入力は「不明」にします。
ツール名・呼出ID・構造化された終了状態などがない形式では、観測の網羅性は保証できません。
エラーの単語を含むだけの結果は失敗に数えません。終了状態の判明件数も表示します。
ツール結果の文字数はログ上の文字数で、実際にモデルへ送信された量やトークン数とは異なります。
直前のツールと入力増加の対応は周辺情報であり、因果関係の証明ではありません。

### リポジトリと追跡情報

ログのリポジトリURLを優先し、不足する場合は現在のローカルGitのoriginでグループ化します。
URLの認証情報・クエリは出力しません。originも不明な場合はGit共通ディレクトリを使い、
リンクしたworktreeをまとめます。Gitがない・フォルダが削除済みなどの場合は作業ディレクトリを使います。
現在のGit情報は過去の所属を保証しないため、各セッションに特定の根拠を表示します。
別ホストへの移転・リポジトリの改名は自動で同一視しません。作業中に場所を変えた場合も最初に記録された場所を使います。

今回の指標にはローカル情報で足りるため、Entireとの連携や外部への保存は追加していません。
ローカルに残らない成果や品質を将来照合する場合は、別途評価方法を設計する必要があります。

## 集計の定義と制約

- Claude Codeは `assistant.message.usage` を応答IDでまとめ、ストリーミングの重複を除きます。
  入力トークンは通常入力・キャッシュ読取・キャッシュ書込の合計です。
- Codexは `token_usage_record.payload.usage` を応答IDで重複排除します。
  この記録がないファイルでは `token_count.info.total_token_usage` の累積増分を使います。
  両形式が同居するファイルでは、新形式を優先します。
  新形式への移行途中のログでは、旧形式にしかない使用量が集計対象から外れる場合があります。
- Codexの入力はキャッシュを、出力は推論を含みます。内数を総量に再加算しません。
- 「使用量記録数」はClaudeでは応答単位、Codexの旧形式では累積増分単位です。
  厳密なAPI呼出回数やユーザーの発言回数ではありません。
- セッション数は期間内に日時付きログがあるセッションの数です。
  使用量が記録されていないセッションも区別して表示します。
- 日別の使用量は記録日時で分類します。日時のない使用量は除外し、件数を表示します。
  モデル不明は `unknown`、不正行・書込途中の行は読み飛ばして件数を表示します。
- 同じ場所に同名の `.jsonl` と圧縮版がある場合、非圧縮版を優先して一度だけ集計します。
  読み取りに失敗した場合は別の圧縮版を試します。
  圧縮形式が破損・途中切れの場合、そのファイル全体の使用量を除外して件数を表示します。
  他のログの集計は続けます。JSON自体の不正行は非圧縮ログと同様に行単位で読み飛ばします。
- 画面には読取成功数・検出数・読取済み圧縮ファイル数を表示します。
  Zstandard非対応のPythonでは `.zst` を読み飛ばし、Python 3.14以降が必要であることと件数を表示します。
  その他の未対応形式も件数を表示します。
- セッションIDや応答IDによる重複排除は圧縮ログにも適用します。
  コピーやフォークなど、ログの作り方によってはセッションをまたぐ重複が残る場合があります。
- ローカルに残るログのみが対象です。削除済みログ、Claude Desktopの通常チャット、
  契約の利用上限・残量・請求額は扱いません。Codex Desktopも同じ形式のローカルログがある場合が対象です。
- ログを読み、ツール引数は反復検出用のハッシュに変換します。
  会話本文・ツール引数・コマンド・ツール結果本文・反復検出用ハッシュはレポートに含めません。
  追跡用にセッションID・リポジトリ名・作業パス・元ログパス・展開後の行番号をHTMLとJSONへ出力します。
  元ログを変更せず、外部通信もしません。HTMLは外部リソースを参照しません。
  出力は一時ファイルから置換するため、出力先が元ログへのハードリンクでも元ログを保持します。
  生成物には追跡情報・利用日時・モデル・利用量が含まれるため、共有する場合は内容を確認してください。
- このレポートは子セッションもID別に表示し、日付単位で期間を区切ります。既存のPrometheus・表形式レポートとは
  集約単位と期間の定義が異なるため、値を直接一致させて比較しません。
- 全ログを毎回読み込むスナップショット方式です。OTLP受信、DB保存、常駐監視、会話要約は未実装です。

形式の確認元:
[Claude Codeのセッション保存先](https://code.claude.com/docs/en/sessions)、
[Claudeの使用量定義](https://code.claude.com/docs/en/agent-sdk/cost-tracking)、
[Codexのプロトコル実装](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)、
[Python標準のZstandard機能](https://docs.python.org/3/library/compression.zstd.html)、
[Gitのリポジトリ検出](https://git-scm.com/docs/git-rev-parse)、
[Git設定の読取](https://git-scm.com/docs/git-config)。
記録形式の変更により、未観測の形式は集計できない場合があります。CIでは合成ログを使って検証します。

## 検証

```bash
mise run test
git diff --check
```

合成ログで重複排除、期間・タイムゾーン境界、旧・新Codex形式、部分書込、
欠損ログ、HTMLエスケープ、本文非出力、CLIと元ログの上書き防止を検証します。
圧縮ログについては過去期間の集計、Zstandardの連結フレーム、gzip、非圧縮版との重複排除、
破損・途中切れからの継続、Zstandard非対応時の案内と元ファイルの保持を検証します。
Zstandard対応のPythonではすべてのテストを実行し、非対応環境ではZstandard実体のテストのみスキップします。
効率指標は、数値の定義・期間境界・ツール記録の重複・欠損時の不明表示・
根拠とヒント・本文や引数の非出力・リンク先・HTMLエスケープ・実際のGit worktreeでの所属検出を検証します。
